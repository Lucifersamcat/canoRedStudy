MÓDULO 06

NAT/PAT, IPv6 y Diagnóstico de Red

Cómo las IPs privadas llegan a Internet gracias a NAT, los fundamentos del protocolo IPv6 que reemplaza a IPv4, y las herramientas de diagnóstico que un técnico usa a diario para verificar y solucionar problemas de red.

Teoría ampliada

El problema del agotamiento de IPv4 y NAT

IPv4 usa direcciones de 32 bits, lo que entrega solo 4 300 millones de combinaciones. En 2011, IANA asignó el último bloque disponible. La solución práctica fue combinar dos mecanismos: las direcciones privadas RFC 1918 (que no se enrutan en Internet) con NAT (Network Address Translation), que traduce esas IPs privadas a una o pocas IPs públicas cuando el tráfico sale hacia Internet.

Tipos de NAT

  • NAT estático: un mapeo fijo entre una IP privada y una IP pública (1-a-1). Se usa cuando un servidor interno debe ser accesible desde Internet con una IP pública fija (ej. servidor de correo, cámara IP accesible remotamente).
  • NAT dinámico: el router tiene un pool de IPs públicas y las asigna temporalmente a los hosts internos según el orden de solicitud. Menos común hoy.
  • PAT / NAT overload: todos los hosts internos comparten una sola IP pública. El router distingue las sesiones usando el número de puerto TCP/UDP. Si PC-A usa el puerto 49152 y PC-B usa 52840, ambas peticiones salen por la misma IP pública pero con puertos diferentes, y el router sabe a cuál PC entregar la respuesta. Este es el modelo que usa prácticamente toda pyme y hogar.

IPv6 — La solución permanente

IPv6 usa direcciones de 128 bits escritas en hexadecimal separado por colones:

2001:0db8:85a3:0000:0000:8a2e:0370:7334

Dos reglas de compresión: los ceros iniciales de cada grupo se omiten, y un bloque continuo de grupos todo-cero se reemplaza por :: (solo una vez por dirección).

  • Global unicast (2000::/3): equivalente a la IP pública de IPv4, enrutable en Internet.
  • Link-local (fe80::/10): se auto-asigna en cada interfaz al arrancar; solo válida en el segmento local, no se enruta.
  • Loopback (::1): equivalente a 127.0.0.1 en IPv4.
  • SLAAC: el host construye su propia IPv6 global combinando el prefijo anunciado por el router con su identificador de interfaz (derivado de la MAC). No necesita DHCP.
  • Dual-stack: un dispositivo opera IPv4 e IPv6 simultáneamente; usa IPv6 si está disponible, cae a IPv4 si no.

Herramientas de diagnóstico de red

Un técnico de redes usa estas utilidades a diario para verificar conectividad y localizar fallas:

  • ping: envía paquetes ICMP Echo Request y espera el Echo Reply. Mide el RTT (round-trip time) en milisegundos y el TTL restante. Si no hay respuesta, hay un problema de conectividad o el host bloquea ICMP.
  • traceroute / tracert: envía paquetes con TTL incrementando (1, 2, 3…). Cada router que descarta el paquete por TTL=0 responde con un mensaje ICMP "Time Exceeded", revelando su IP. El resultado es la ruta completa salto a salto hasta el destino.
  • nslookup: consulta el servidor DNS para resolver nombres. Permite verificar registros A (IPv4), AAAA (IPv6), MX (correo) y NS (servidor DNS autoritativo).
  • netstat -an: muestra las conexiones TCP/UDP activas del sistema y los puertos en escucha (LISTENING). Útil para verificar qué servicios están corriendo.
  • Wireshark: captura paquetes a nivel de interfaz de red. Permite ver exactamente qué tráfico circula, analizar handshakes, detectar retransmisiones, errores de DHCP, etc. Se filtra con expresiones como ip.addr == 192.168.1.10, tcp.port == 80 o dhcp.

Comandos esenciales

# NAT overload (PAT) — router Cisco
ip access-list standard ACL_LAN
 permit 192.168.1.0 0.0.0.255

interface gi0/0           # LAN (inside)
 ip nat inside

interface gi0/1           # WAN (outside, IP pública)
 ip nat outside

ip nat inside source list ACL_LAN interface gi0/1 overload

# NAT estático para un servidor interno
ip nat inside source static 192.168.1.100 200.1.1.2

# Verificación NAT
show ip nat translations
show ip nat statistics
# Diagnóstico — Windows / Linux
ping 8.8.8.8                       # conectividad + RTT
tracert 8.8.8.8                    # ruta salto a salto (Windows)
traceroute 8.8.8.8                 # ruta salto a salto (Linux/Mac)
nslookup google.com                # resolución DNS tipo A
nslookup -type=MX dominio.com      # registros de correo
netstat -an                        # conexiones y puertos activos

# Filtros básicos en Wireshark
ip.addr == 192.168.1.10            # todo el tráfico de esa IP
tcp.port == 80                     # solo HTTP
icmp                               # solo pings
dhcp                               # proceso DORA completo

Laboratorio 6 — NAT overload en Packet Tracer

Topología: 3 PCs en LAN (192.168.1.x/24), un router Cisco, y un servidor HTTP simulando Internet.

  1. Crear la topología en Packet Tracer: 3 PCs conectados a un switch, switch a Gi0/0 del router; servidor HTTP en Gi0/1 (la "WAN").
  2. Asignar IPs a los PCs (192.168.1.10–12/24, gateway 192.168.1.1) y al router Gi0/0 (192.168.1.1/24).
  3. Asignar la IP "pública" a Gi0/1 del router (ej. 200.1.1.1/30) y al servidor (200.1.1.2/30).
  4. Crear la ACL: ip access-list standard ACL_LAN permit 192.168.1.0 0.0.0.255
  5. Aplicar NAT: ip nat inside source list ACL_LAN interface gi0/1 overload
  6. Marcar las interfaces: ip nat inside en Gi0/0 y ip nat outside en Gi0/1.
  7. Desde los tres PCs, hacer ping al servidor (200.1.1.2) y navegar al servidor HTTP.
  8. Verificar la tabla NAT con show ip nat translations y observar los tres mapeos de puerto.
Diagnóstico adicional En tu PC real, abre una terminal y ejecuta tracert 8.8.8.8 (Windows) o traceroute 8.8.8.8 (Linux/Mac). Identifica el primer salto (tu router doméstico), el segundo (el router del ISP), y los siguientes saltos hacia los servidores de Google. Eso es tu NAT en acción.

Flashcards

Haz clic en cada tarjeta para ver la respuesta.

¿Qué problema motivó la creación de NAT?
El agotamiento de direcciones IPv4. NAT permite que miles de hosts compartan una sola IP pública usando el número de puerto como diferenciador (PAT/overload).
Diferencia entre NAT estático y PAT
NAT estático es un mapeo fijo 1-a-1 (para servidores con IP pública fija). PAT multiplexa muchos hosts en una sola IP pública usando distintos puertos TCP/UDP.
¿Cuántos bits tiene IPv6 y en qué formato?
128 bits, escritos en hexadecimal separado por colones (::). Los grupos de ceros consecutivos se comprimen con "::".
¿Qué es una dirección link-local IPv6?
Prefijo fe80::/10. Se autoconfigura en cada interfaz al arrancar. Solo es válida dentro del segmento local; no se enruta hacia otros segmentos.
¿Qué protocolo usa ping y qué mide?
ICMP (Echo Request / Echo Reply). Mide conectividad básica y el RTT (round-trip time) en milisegundos. El TTL indica cuántos saltos quedan disponibles.
¿Qué ventaja tiene traceroute sobre ping?
Muestra cada router (salto) en la ruta hacia el destino. Si hay pérdida de paquetes o alta latencia, traceroute indica exactamente en qué salto ocurre el problema.

Cuestionario

1. ¿Qué tipo de NAT usan casi todas las pymes y hogares para que varios hosts compartan una sola IP pública?
PAT (Port Address Translation / NAT overload) multiplexa muchos hosts privados en una sola IP pública usando el número de puerto como diferenciador.
2. ¿Cuántos bits tiene una dirección IPv6?
IPv6 usa 128 bits escritos en 8 grupos de 4 dígitos hexadecimales separados por colones, entregando 3.4 × 10³⁸ combinaciones.
3. ¿Cuál es la dirección de loopback en IPv6?
::1 es el loopback IPv6 (equivalente a 127.0.0.1 en IPv4). fe80::1 es una dirección link-local, no el loopback.
4. ¿Qué herramienta muestra los routers intermedios en la ruta hacia un destino?
traceroute/tracert usa TTL incrementales: cada router que descarta un paquete por TTL=0 responde revelando su IP, exponiendo la ruta completa salto a salto.
5. ¿Qué protocolo utiliza el comando ping para verificar conectividad?
ping usa ICMP Echo Request y espera un ICMP Echo Reply. No usa TCP ni UDP; es un protocolo de capa 3 para diagnóstico de red.
