MÓDULO 05

Virtualización

La virtualización permite ejecutar múltiples sistemas operativos sobre un mismo servidor físico. Proxmox, KVM y LXC son las herramientas del técnico moderno para construir infraestructura eficiente, ágil y con alta disponibilidad.

Teoría ampliada

¿Por qué virtualizar?

La virtualización permite que un servidor físico ejecute múltiples sistemas operativos simultáneamente. Antes de la virtualización, cada servicio requería su propio servidor físico, lo que significaba hardware subutilizado, alto consumo eléctrico y muchos puntos de falla. Con virtualización, un servidor con 32 cores y 128 GB de RAM puede alojar docenas de máquinas virtuales independientes.

Los cuatro pilares del beneficio: Eficiencia (maximizar recursos), Agilidad (nuevas VMs en segundos), Disponibilidad (HA, backups de VM como archivos) y Ahorro (menos hardware, menos energía, menos espacio).

Hypervisores: Tipo 1 vs Tipo 2

El hypervisor es la capa de software que abstrae el hardware y permite correr múltiples sistemas operativos sobre él:

  • Tipo 1 (Bare-Metal): Se instala directamente sobre el hardware, sin sistema operativo host. Es el más eficiente y usado en producción. Ejemplos: Proxmox, VMware ESXi, Microsoft Hyper-V, KVM.
  • Tipo 2 (Hosted): Se instala como una aplicación sobre un sistema operativo convencional. Menor rendimiento, ideal para pruebas y desarrollo. Ejemplos: VMware Workstation, VirtualBox, Parallels Desktop.

KVM — Kernel-Based Virtual Machine

KVM convierte el kernel de Linux en un hypervisor de Tipo 1. Fue creado por Qumranet y adquirido por Red Hat en 2008. Es el motor de virtualización sobre el que se basa Proxmox para crear y gestionar máquinas virtuales completas. Cada VM tiene acceso a CPU, RAM, almacenamiento y red virtualizados completamente aislados del host.

LXC — Linux Containers

LXC (Linux Containers) virtualiza a nivel de sistema operativo, no de hardware. Los containers comparten el kernel del host pero tienen su propio sistema de archivos, red, usuarios y procesos. Son más ligeros y rápidos que las VMs completas (arrancan en menos de 5 segundos) pero su sistema operativo invitado debe ser Linux.

Proxmox VE

Proxmox Virtual Environment es una distribución bare-metal basada en Debian que integra KVM (para VMs completas) y LXC (para containers). Ofrece una interfaz web completa, clustering de servidores, migración en vivo, backups automáticos y conexión a almacenamiento compartido (NFS, iSCSI, Ceph). Es la plataforma de virtualización más usada en empresas medianas que no pueden pagar licencias de VMware.

VM vs Container Usa una VM cuando necesitas un OS diferente al host o aislamiento total. Usa un container LXC cuando quieres ligereza y velocidad en un servicio Linux (web server, DNS, base de datos).

Redes en virtualización: el switch virtual

Aquí es donde virtualización y redes se cruzan. Las VMs no se conectan a un puerto físico: se conectan a un switch virtual (o bridge) que vive dentro del hypervisor. En Proxmox ese bridge se llama vmbr0 por defecto y funciona como un switch de capa 2 por software: aprende MACs, reenvía tramas entre las VMs y las saca al exterior por la tarjeta física del host (la "uplink"). Cada VM recibe una NIC virtual (lo ideal es el driver virtio, el más rápido) con su propia MAC.

Como es un switch, también entiende VLANs: se puede etiquetar el tráfico de una VM con un VLAN ID (VLAN-aware bridge), igual que en un switch físico. Así varias VMs en el mismo host quedan segmentadas en redes distintas.

Modos de red de una VM

  • Bridged (puente): la VM se conecta al bridge y aparece en la red física como un equipo más, con IP del mismo rango que el host. Es el modo de producción.
  • NAT: el hypervisor traduce las direcciones; la VM sale a Internet usando la IP del host pero no es accesible directamente desde la red. Útil en laboratorios con una sola IP.
  • Host-only / interna: la VM solo ve al host y a otras VMs del mismo segmento virtual; sin salida a Internet. Ideal para laboratorios aislados.

Snapshot vs Backup

Se confunden, pero no son lo mismo. Un snapshot congela el estado de una VM en un instante para revertir un cambio rápido (una actualización que salió mal); depende del almacenamiento original, por lo que no sirve como respaldo. Un backup es una copia completa e independiente (un archivo) que se guarda en otro almacenamiento y permite restaurar la VM aunque el disco original se pierda.

LXC vs Docker

Ambos son contenedores, pero con filosofías distintas. LXC es un contenedor de sistema: se comporta como una máquina Linux ligera completa (con su init, servicios y SSH), pensado para correr de forma persistente. Docker es un contenedor de aplicación: empaqueta un solo proceso/servicio y su entorno, pensado para ser efímero y desplegado a escala. Proxmox usa LXC; en producción moderna de aplicaciones suele usarse Docker (a menudo dentro de una VM).

Regla práctica de red Si una VM no tiene conectividad, revisa en este orden: (1) la NIC virtual está conectada al bridge correcto, (2) el modo de red (bridged vs NAT) es el esperado, (3) el VLAN tag coincide con la red, y (4) la IP/gateway dentro de la VM. El 90% de los fallos están en los primeros dos puntos.

Diagrama — Tipo 1 vs Tipo 2

Tipo 1 es más eficiente porque no tiene OS intermediario. Tipo 2 es más sencillo de instalar y usar para laboratorios y desarrollo.
Aquí se cruzan redes y virtualización: el bridge vmbr0 es un switch de capa 2 por software. Entiende VLANs, por lo que varias VMs del mismo host pueden vivir en redes distintas y salir por un trunk al switch físico.
Bridged pone la VM en la red real (producción); NAT la oculta tras la IP del host (laboratorios). Un tercer modo, host-only, aísla la VM sin salida a Internet.

Comandos — Proxmox y red virtual

Proxmox tiene interfaz web, pero todo se puede hacer por CLI. qm gestiona VMs (KVM), pct gestiona contenedores (LXC), y la red se define en el host como un bridge de Linux.

# --- VMs con qm (KVM) ---
qm list                          # listar VMs y su estado
qm start 100                     # arrancar la VM 100
qm snapshot 100 antes-update     # crear un snapshot
qm set 100 -net0 virtio,bridge=vmbr0   # NIC virtio en el bridge vmbr0
qm set 100 -net0 virtio,bridge=vmbr0,tag=10  # misma NIC en la VLAN 10

# --- Contenedores con pct (LXC) ---
pct list                         # listar contenedores
pct start 200                    # arrancar el CT 200
pct enter 200                    # abrir una shell dentro del contenedor

# --- El bridge en el host (Debian/Proxmox) ---
ip -br link show type bridge     # ver los bridges (vmbr0...)
brctl show                       # qué interfaces cuelgan de cada bridge
# La config persistente vive en /etc/network/interfaces (iface vmbr0)

# --- Backup completo de una VM ---
vzdump 100 --storage backups --mode snapshot
Snapshot ≠ backup qm snapshot sirve para revertir un cambio rápido, pero vive en el mismo disco. Para un respaldo real usa vzdump, que genera un archivo independiente en otro almacenamiento.

Laboratorio 5 — Virtualización en Digital Ocean

  1. Crear una cuenta gratuita en Digital Ocean (digitalocean.com).
  2. Crear un Droplet (VM) Linux Ubuntu 22.04 — tamaño mínimo (1 vCPU, 1 GB RAM).
  3. Conectarse por SSH usando el terminal: ssh root@IP_DEL_DROPLET.
  4. Crear un segundo Droplet con Windows Server — observar la diferencia de recursos requeridos.
  5. Verificar si los servicios son accesibles públicamente por IP (HTTP, SSH).
  6. Destruir ambos Droplets al finalizar para no generar cargos.
Alternativa local Si no puedes usar Digital Ocean, instala VirtualBox (Tipo 2) y crea una VM de Ubuntu Server 22.04 en tu máquina. Los conceptos son idénticos.

Resumen del módulo

  • Virtualizar permite que un servidor físico aloje muchas VMs: eficiencia, agilidad, disponibilidad y ahorro.
  • Tipo 1 (bare-metal: Proxmox, ESXi) es más eficiente que Tipo 2 (hosted: VirtualBox).
  • KVM da VMs completas; LXC da contenedores ligeros que comparten el kernel del host.
  • Las VMs se conectan a un bridge virtual (vmbr0) que actúa como switch L2 y entiende VLANs.
  • Modos de red: bridged (la VM aparece en la red real), NAT (sale tras la IP del host), host-only (aislada).
  • Snapshot ≠ backup: el snapshot revierte un cambio rápido; el backup (vzdump) es una copia independiente.

¿Qué es el bridge vmbr0 en Proxmox?
Un switch virtual de capa 2 por software al que se conectan las NICs de las VMs; reenvía tramas entre ellas y las saca al exterior por la tarjeta física del host. Soporta VLANs.
Diferencia entre snapshot y backup
El snapshot congela el estado para revertir un cambio, pero vive en el mismo disco. El backup es una copia completa e independiente en otro almacenamiento; sí protege ante pérdida del disco.
¿Qué es un hypervisor Tipo 1?
Se instala directamente sobre el hardware (bare-metal) sin OS intermediario. Más eficiente. Ej: Proxmox, ESXi, Hyper-V.
¿Qué es KVM?
Kernel-Based Virtual Machine — módulo del kernel Linux que lo convierte en hypervisor Tipo 1. Es el motor de VMs en Proxmox.
¿Diferencia entre VM y Container LXC?
Una VM virtualiza el hardware completo y tiene su propio kernel. Un Container LXC comparte el kernel del host — más ligero y rápido.
¿En qué se basa Proxmox VE?
En Debian Linux. Integra KVM para VMs completas y LXC para containers. Incluye interfaz web, clustering y backup.
¿Qué es un Snapshot en virtualización?
Una foto del estado completo de una VM en un instante. Permite revertir la VM a ese estado si algo falla (rollback).
¿Por qué se dice que LXC arranca en segundos?
Porque comparte el kernel del host y no necesita arrancar un OS completo — solo inicializa el entorno de usuario aislado.

Cuestionario

2. KVM es un sistema de virtualización del…

3. Un container LXC frente a una VM…
