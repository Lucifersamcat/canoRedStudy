RADIUS Server Windows

Una contraseña WiFi compartida no escala ni es segura en una empresa. RADIUS permite que cada usuario se autentique con sus propias credenciales — las mismas del dominio — usando el rol NPS de Windows Server integrado con Active Directory.

Teoría ampliada

¿Qué es RADIUS y qué resuelve?

RADIUS (Remote Authentication Dial-In User Service) es un protocolo de AAA: Authentication (¿quién eres?), Authorization (¿qué puedes hacer?) y Accounting (¿qué hiciste?). Centraliza la autenticación: en lugar de configurar credenciales en cada switch o AP, todos consultan a un servidor único.

Opera sobre UDP: puerto 1812 para autenticación/autorización y 1813 para accounting.

NPS: el RADIUS de Microsoft

NPS (Network Policy Server) es la implementación de RADIUS incluida como rol en Windows Server. Su gran ventaja es que se integra de forma nativa con Active Directory: las credenciales y los grupos ya existen en el dominio, así que NPS valida directamente contra el AD sin duplicar usuarios.

Los actores del flujo

  • Cliente RADIUS / NAS (Network Access Server): el dispositivo que consulta a RADIUS — un switch, un AP, o el controller UniFi. No es el usuario final.
  • Servidor RADIUS: el NPS que valida las credenciales.
  • Almacén de cuentas: Active Directory, donde viven usuarios y grupos.
  • Shared Secret: contraseña compartida entre el cliente RADIUS y el servidor; cifra y autentica los mensajes RADIUS entre ellos. Si no coincide, el servidor ignora al cliente.

Las dos políticas de NPS

NPS distingue dos tipos de política y confundirlas es un error frecuente:

  • Connection Request Policy: decide dónde se procesa la petición (en este NPS o reenviada a otro servidor) y filtra por tipo de conexión.
  • Network Policy: decide quién entra y cómo: condiciona por grupo de AD, define el método de autenticación (MS-CHAPv2, PEAP, EAP) y concede o deniega el acceso. Puede además enviar atributos como el VLAN ID a asignar.

¿Por qué registrar el NPS en AD?

Registrar el NPS en Active Directory le otorga permiso para leer las propiedades de dial-in de las cuentas de usuario. Sin ese registro, NPS no puede consultar correctamente al AD y las autenticaciones fallan aunque las credenciales sean válidas.

Aclaración sobre las IPs del material original En el material original se ve la IP 192.168.1.5 como cliente RADIUS y 192.168.1.100 como servidor NPS. No es una contradicción: 192.168.1.5 es el cliente (el controller/AP UniFi que pregunta) y 192.168.1.100 es el servidor NPS (el que responde). El Shared Secret debe ser idéntico en ambos lados.

Configuración de NPS — paso a paso

# 1. Instalar el rol NPS en Windows Server
Server Manager → Add Roles and Features
  → Network Policy and Access Services → Network Policy Server

# 2. Registrar NPS en Active Directory (¡imprescindible!)
Consola NPS → clic derecho en "NPS (Local)"
  → Register server in Active Directory

# 3. Agregar el cliente RADIUS (el controller/AP UniFi)
NPS → RADIUS Clients and Servers → RADIUS Clients → New
  Friendly name : UniFi-Controller
  IP address    : 192.168.1.5          # el dispositivo que pregunta
  Shared Secret : ClaveSegura123!       # idéntico en UniFi

# 4. Connection Request Policy
NPS → Policies → Connection Request Policies → New
  Condition  : NAS Port Type = Wireless - IEEE 802.11 / Ethernet
  Settings   : Authenticate requests on this server

# 5. Network Policy
NPS → Policies → Network Policies → New
  Condition      : Windows Groups = GRP_WiFi_Empresarial
  Access Permission : Access granted
  Auth methods   : MS-CHAPv2  (o PEAP para 802.1X — ver Bloque 5)

Integración con UniFi

# En el UniFi Controller
Settings → Profiles → RADIUS → Create New RADIUS Profile
  RADIUS Server IP : 192.168.1.100      # la IP del servidor NPS
  Port             : 1812
  Shared Secret    : ClaveSegura123!     # idéntico al de NPS

# Luego se asigna este perfil RADIUS a la red WiFi (Bloque 5)

Diagrama de la topología

Laboratorio 4: el AP/controller actúa como cliente RADIUS; NPS valida contra los grupos de Active Directory.
El supplicant (PC) habla EAPOL con el NAS (switch/AP). El NAS reenvía en RADIUS al servidor NPS. NPS valida en Active Directory. Si las credenciales son válidas, el NAS recibe Access-Accept y habilita el puerto de red.

Laboratorio 4 — RADIUS con AD

Topología: AD + NPS → UniFi Controller → AP → Cliente WiFi.

  1. Instalar y configurar el rol NPS en Windows Server.
  2. Registrar el NPS en Active Directory.
  3. Crear el grupo en AD: GRP_WiFi_Empresarial.
  4. Agregar usuarios de prueba al grupo.
  5. Añadir el cliente RADIUS (UniFi) con su IP y Shared Secret.
  6. Crear la Connection Request Policy y la Network Policy condicionada al grupo.
  7. Configurar el perfil RADIUS en UniFi apuntando al NPS.
  8. Probar la autenticación con un usuario del AD y revisar el Event Viewer del NPS.
Verificación En Event Viewer → Custom Views → Server Roles → Network Policy and Access Services debe aparecer un evento de Access Granted tras un login correcto, o Access Rejected con el motivo si falla.

Resumen del bloque

  • RADIUS centraliza la autenticación (AAA); usa UDP 1812 (auth) y 1813 (accounting).
  • NPS es el RADIUS de Microsoft y se integra de forma nativa con Active Directory.
  • El cliente RADIUS (NAS) es el switch/AP/controller, no el usuario final.
  • El Shared Secret debe ser idéntico en el cliente y en el servidor.
  • Connection Request Policy decide dónde se procesa; Network Policy decide quién entra y cómo.
  • Registrar el NPS en AD es obligatorio para que pueda leer las cuentas de usuario.

Cuestionario

1. ¿En qué puerto opera RADIUS para autenticación?
1812 es autenticación/autorización; 1813 es accounting.
2. El cliente RADIUS (NAS) es…
El NAS es el dispositivo de red que pregunta; el usuario final es el supplicant.
3. Si el Shared Secret no coincide entre cliente y servidor…
El Shared Secret autentica al cliente; sin coincidencia, no hay diálogo válido.
4. ¿Qué política de NPS condiciona el acceso por grupo de AD?
La Network Policy define quién entra (grupo), cómo (método) y con qué atributos.
5. ¿Por qué hay que registrar el NPS en Active Directory?
Sin el registro, NPS no puede consultar las propiedades de las cuentas y la auth falla.
