BLOQUE 03

Switches Ubiquiti

Frente a la CLI de Cisco, Ubiquiti propone una gestión centralizada y gráfica: el UniFi Controller administra switches y APs desde una sola interfaz. El reto es traducir lo que ya sabes de VLANs a la lógica de UniFi.

Teoría ampliada

El modelo de gestión UniFi

En Cisco cada switch se configura individualmente por CLI. En Ubiquiti, un software llamado UniFi Network Controller (o Network Application) actúa como cerebro central: descubre los dispositivos, les empuja la configuración y muestra estadísticas en tiempo real. El controller puede correr en un PC/servidor, en una VM, o en un appliance dedicado de Ubiquiti (Cloud Key / consola Dream Machine).

Punto clave: una vez configurado, el controller no necesita estar encendido permanentemente para que la red funcione — los dispositivos conservan su configuración. Pero sí se necesita para hacer cambios, ver estadísticas y aplicar actualizaciones.

Adopción de dispositivos

Adoptar es el proceso de poner un dispositivo Ubiquiti bajo el control de un controller concreto. Un equipo recién sacado de la caja está en estado Pending Adoption; al adoptarlo, el controller le entrega su configuración y lo "reclama". El dispositivo y el controller deben poder verse en la red (capa 2 por descubrimiento, o capa 3 mediante inform URL / DNS).

VLANs en lenguaje UniFi

UniFi no habla de "VLAN" en su menú principal: habla de Networks. Crear una Network con un VLAN ID equivale exactamente a declarar una VLAN. Los puertos del switch se configuran con Port Profiles, que son el equivalente gráfico a un puerto access o trunk:

  • Un perfil tipo Native VLAN + Tagged permitiendo varias redes = un trunk.
  • Un perfil con una sola Network nativa = un access port.

PoE: alimentar por el cable de red

Los switches UniFi suelen ser PoE (Power over Ethernet): entregan electricidad y datos por el mismo cable Ethernet. Esto es esencial para los APs WiFi, que normalmente se montan en el techo donde no hay tomacorriente. El controller permite incluso encender/apagar el PoE de un puerto de forma remota.

Corrección al material original Los comandos de instalación del material original están desactualizados: apt-key está obsoleto y la línea wget ... debian stable InRelease es incorrecta. Lo más fiable hoy es usar el script de instalación oficial de la comunidad (UniFi Easy Installer) o seguir la guía vigente de Ubiquiti, que añade el repositorio con una clave GPG en /usr/share/keyrings/. Para un laboratorio, la opción más simple es instalar el controller directamente en Windows con el ejecutable oficial.

Instalación del UniFi Controller

# --- Opción A: Windows (recomendada para laboratorio) ---
# 1. Descargar el instalador desde ui.com/download/unifi
# 2. Ejecutar UniFi-installer.exe (instala Java + MongoDB embebido)
# 3. Acceder vía navegador a:  https://localhost:8443

# --- Opción B: Linux (Ubuntu/Debian) — método vigente ---
# Repositorio con clave GPG en keyrings (sustituye al obsoleto apt-key)
curl -fsSL https://dl.ui.com/unifi/unifi-repo.gpg | \
  sudo tee /usr/share/keyrings/unifi-repo.gpg > /dev/null

echo 'deb [signed-by=/usr/share/keyrings/unifi-repo.gpg] https://www.ui.com/downloads/unifi/debian stable ubiquiti' | \
  sudo tee /etc/apt/sources.list.d/unifi.list

sudo apt update
sudo apt install unifi      # instala UniFi + MongoDB + Java como dependencias

# Gestionar el servicio
sudo systemctl enable unifi
sudo systemctl start unifi
sudo systemctl status unifi

# Acceso web
# https://IP_DEL_SERVIDOR:8443
Nota de versiones Cada versión de UniFi exige una versión concreta de MongoDB y Java. Si instalas en Linux, consulta la matriz de compatibilidad oficial antes de elegir versiones; en Windows el instalador resuelve todo automáticamente.

Flujo de configuración en la GUI

  1. Setup inicial: crear el Site y la cuenta de administrador.
  2. Adopt devices: descubrir y adoptar switches y APs de la red.
  3. Crear Networks: Settings → Networks → Add Network, asignando el VLAN ID.
  4. Configurar Port Profiles: definir qué redes permite cada perfil de puerto.
  5. Asignar perfiles a puertos: Devices → Switch → Ports.
  6. Verificar: vista de topología y estadísticas por puerto.

Laboratorio 3 — UniFi Switch con VLANs

Objetivo: crear 3 redes — VLAN 10 Empleados, VLAN 20 Invitados, VLAN 30 Gestión.

  1. Instalar el UniFi Controller en un servidor o VM (o en Windows para el laboratorio).
  2. Completar el setup inicial: crear el Site y la cuenta admin.
  3. Adoptar el switch Ubiquiti desde la sección Devices.
  4. Crear las 3 Networks con sus VLAN IDs (10, 20, 30).
  5. Crear un Port Profile por cada red, y un perfil trunk para el enlace ascendente.
  6. Asignar cada puerto del switch a su perfil correspondiente.
  7. Conectar PCs de prueba y verificar la segmentación con pings entre VLANs.
Verificación Bien hecho si: el switch aparece como Connected en el controller, los puertos muestran su perfil asignado, y los PCs solo se comunican dentro de su propia VLAN.

Resumen del bloque

  • El UniFi Controller gestiona de forma centralizada y gráfica todos los dispositivos Ubiquiti.
  • Adoptar = poner un dispositivo bajo el control de un controller concreto.
  • En UniFi, una Network con VLAN ID equivale a una VLAN; los puertos se configuran con Port Profiles.
  • El PoE alimenta APs y otros dispositivos por el cable de red, sin tomacorriente cercano.
  • Tras configurar, los dispositivos funcionan aunque el controller esté apagado; este solo se necesita para cambios y estadísticas.

¿Qué es el UniFi Controller?
Software de gestión centralizada que descubre, configura y monitoriza los dispositivos Ubiquiti.
¿Qué significa "adoptar" un dispositivo?
Ponerlo bajo el control de un controller concreto, que le entrega su configuración.
¿Cómo se define una VLAN en UniFi?
Creando una Network y asignándole un VLAN ID en Settings → Networks.
¿Qué es un Port Profile?
Un perfil reutilizable que define qué redes/VLANs permite un puerto; equivale a access o trunk.
¿Para qué sirve el PoE?
Entrega energía y datos por el mismo cable Ethernet; clave para alimentar APs en el techo.
¿La red deja de funcionar si se apaga el controller?
No: los dispositivos conservan su configuración. El controller solo hace falta para cambios y estadísticas.

Cuestionario

1. En UniFi, ¿qué elemento equivale a una VLAN?
Una Network con VLAN ID es la VLAN; el Port Profile decide qué puertos la usan.
2. Adoptar un dispositivo significa…
La adopción reclama el equipo y le envía su configuración.
3. ¿Para qué se usa principalmente el PoE en una red UniFi?
PoE lleva energía + datos; ideal para APs montados donde no hay tomacorriente.
4. Si se apaga el UniFi Controller tras configurar la red…
Los dispositivos conservan su config; el controller solo es necesario para gestionar.
5. ¿Qué ventaja principal ofrece la gestión con UniFi frente a la CLI?
Un solo panel configura y monitoriza switches y APs, sin tocar cada equipo por CLI.
