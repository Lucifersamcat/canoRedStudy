BLOQUE 05

WiFi Empresarial Ubiquiti

Aquí convergen los bloques anteriores: VLANs para segmentar, UniFi para gestionar y RADIUS para autenticar. El resultado es WiFi empresarial real, donde cada empleado entra con sus credenciales del dominio mediante 802.1X.

Teoría ampliada

WPA2-Personal vs WPA2-Enterprise

Ambos cifran el WiFi, pero se diferencian en cómo autentican:

  • WPA2-Personal (PSK): una sola contraseña compartida por todos. Si se filtra, hay que cambiarla en todos los dispositivos. No identifica a usuarios individuales. Sirve para hogares o redes de invitados.
  • WPA2-Enterprise: cada usuario se autentica con credenciales propias (usuario/contraseña o certificado) validadas por un servidor RADIUS. Permite revocar a un usuario sin afectar a los demás, registrar quién se conecta y aplicar políticas por persona.
Actualización El estándar actual es WPA3: WPA3-Personal sustituye PSK por SAE (resistente a ataques de diccionario) y WPA3-Enterprise refuerza el cifrado. El concepto 802.1X de este bloque es idéntico en WPA2-Enterprise y WPA3-Enterprise.

802.1X: control de acceso basado en puerto

802.1X es el estándar IEEE que controla el acceso a la red antes de permitir tráfico. Define tres roles:

  • Supplicant: el cliente que quiere entrar (laptop, teléfono).
  • Authenticator: el AP (o switch) que actúa de intermediario; mantiene el "puerto" cerrado hasta que la autenticación tenga éxito.
  • Authentication Server: el servidor RADIUS (NPS) que valida las credenciales.

EAP y sus variantes

EAP (Extensible Authentication Protocol) no es un método único, sino un marco que transporta distintos métodos de autenticación:

  • EAP-MD5: obsoleto e inseguro — no cifra el canal.
  • PEAP: el más usado en entornos Windows. Crea un túnel TLS usando un certificado solo en el servidor, y dentro envía usuario/contraseña (MS-CHAPv2). El cliente no necesita certificado.
  • EAP-TLS: el más seguro — usa certificados en cliente y servidor, pero exige una PKI.

PEAP es más seguro que EAP-MD5 porque las credenciales viajan dentro de un túnel TLS cifrado, no expuestas.

Multi-VLAN wireless

Un mismo AP puede emitir varios SSID, y cada SSID puede mapearse a una VLAN distinta. El enlace del AP al switch es un trunk que transporta todas esas VLANs etiquetadas. Así un solo punto de acceso físico sirve a empleados, invitados y VoIP de forma segregada.

El flujo 802.1X/EAP completo

Cliente (Supplicant)
   |-- EAPOL-Start ----------------> AP (Authenticator)
   |<- EAP Request/Identity --------|
   |-- EAP Response (identidad) --->|-- Access-Request ----> RADIUS (NPS)
   |                                |<- Access-Challenge ---|
   |<==== túnel TLS PEAP ==========>|                       |
   |-- credenciales (MS-CHAPv2) --->|-- Access-Request ----> RADIUS
   |                                |<- Access-Accept ------|  (+ VLAN ID)
   |<- EAP-Success -----------------|
   |========= Conectado a la VLAN asignada =================|

Configuración de WiFi empresarial en UniFi

# SSID corporativo con 802.1X
Settings → WiFi → Add WiFi Network
  Name (SSID)   : Empresa_Secure
  Security      : WPA2/WPA3 Enterprise
  RADIUS Profile: (el perfil NPS creado en el Bloque 4)
  Network/VLAN  : VLAN 10  (Empleados)

# SSID de invitados con PSK simple
Settings → WiFi → Add WiFi Network
  Name (SSID)   : Invitados
  Security      : WPA2/WPA3 Personal
  Password      : ClaveInvitados
  Network/VLAN  : VLAN 20
  Guest Policy  : habilitada (aísla a los clientes entre sí)

# Esquema multi-SSID / multi-VLAN sobre los mismos APs
SSID Empresa_Secure  → VLAN 10  → 802.1X / PEAP   (RADIUS)
SSID Invitados       → VLAN 20  → PSK
SSID VoIP            → VLAN 30  → PSK + QoS
Tip El enlace del AP al switch debe ser un trunk que permita las VLANs 10, 20 y 30; si solo lleva una VLAN, los SSID de las demás no tendrán salida.

Laboratorio 5 — WPA2-Enterprise completo

  1. Verificar que NPS y AD funcionan correctamente (Bloque 4).
  2. Crear el SSID Empresa_Secure con seguridad WPA2/WPA3-Enterprise en UniFi.
  3. Asignar el perfil RADIUS y la VLAN 10 al SSID.
  4. Asegurar que el enlace AP↔switch es un trunk con las VLANs necesarias.
  5. Desde un cliente Windows, conectar al SSID e ingresar credenciales del AD.
  6. Verificar en el Event Viewer del NPS que la autenticación fue exitosa.
  7. Crear un segundo SSID Invitados en VLAN 20 con PSK y Guest Policy.
  8. Comprobar que los clientes de VLAN 10 y VLAN 20 están aislados entre sí.
Verificación Éxito si: el cliente corporativo entra con credenciales del dominio (sin PSK), aparece en la VLAN 10, y un cliente de invitados no puede alcanzar recursos de la VLAN 10.

Resumen del bloque

  • WPA2-Personal usa una clave compartida; WPA2-Enterprise autentica a cada usuario contra RADIUS.
  • 802.1X define tres roles: supplicant, authenticator (AP) y authentication server (RADIUS).
  • EAP es un marco; PEAP protege las credenciales en un túnel TLS con certificado solo en el servidor.
  • Un AP puede emitir varios SSID, cada uno mapeado a una VLAN distinta, sobre un enlace trunk.
  • RADIUS puede devolver el VLAN ID en el Access-Accept para ubicar al usuario en su red.
