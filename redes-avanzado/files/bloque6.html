BLOQUE 06

Multicast con Cisco

Cuando un mismo contenido — IPTV, videoconferencia — debe llegar a muchos receptores, enviar una copia por cada uno satura la red. Multicast envía un único flujo que la red replica solo donde hace falta. PIM e IGMP hacen posible esa magia.

Teoría ampliada

Unicast, broadcast y multicast

Hay tres formas de entregar tráfico IP:

  • Unicast: uno a uno. Para 100 espectadores de un video, el servidor envía 100 flujos idénticos — desperdicio masivo de ancho de banda.
  • Broadcast: uno a todos en la red. Todos reciben, quieran o no; no cruza routers.
  • Multicast: uno a un grupo. El servidor envía un solo flujo y la red lo duplica únicamente en los puntos donde se bifurca hacia receptores interesados.

Grupos multicast

Un grupo multicast se identifica con una dirección IP clase D, en el rango 224.0.0.0 – 239.255.255.255. El rango 239.0.0.0/8 es de uso administrativo/privado (similar a las IP privadas) — típico para IPTV interna. Un receptor "se suscribe" a un grupo; un emisor envía hacia esa dirección de grupo.

IGMP: la suscripción del host

IGMP (Internet Group Management Protocol) es el protocolo con el que un host le dice a su router local "quiero recibir el grupo 239.1.1.1" (un IGMP Join) o "ya no lo quiero" (Leave). IGMP funciona solo entre el host y su router; no propaga el flujo por la red.

IGMP Snooping en el switch

Un switch, por defecto, trata el multicast como broadcast: lo inunda por todos los puertos de la VLAN. IGMP Snooping hace que el switch "espíe" los mensajes IGMP y aprenda qué puertos tienen receptores interesados, enviando el flujo solo a esos puertos. Sin snooping, un stream de video llega incluso a quien no lo pidió.

PIM: el enrutamiento multicast

PIM (Protocol Independent Multicast) construye los árboles de distribución que llevan el flujo entre routers. Es "independiente del protocolo" porque usa la tabla de enrutamiento unicast existente (RIP, OSPF, etc.). Dos modos:

  • PIM Dense Mode (DM): asume que casi todos quieren el flujo. Inunda toda la red y luego poda (prune) las ramas sin receptores. Simple, pero ineficiente; solo para redes pequeñas.
  • PIM Sparse Mode (SM): asume que pocos quieren el flujo. Nadie recibe nada hasta que lo pide explícitamente. Usa un árbol compartido con raíz en el RP. Es el modo recomendado.

El Rendezvous Point (RP)

En PIM-SM, el RP es un router que actúa de "punto de encuentro": los emisores registran su tráfico en el RP y los receptores van al RP a buscarlo. Una vez establecido el flujo, los routers pueden optimizar pasando del árbol compartido a un árbol de camino más corto (SPT). El RP se define de forma estática o dinámica (Auto-RP o BSR).

RPF: anti-loop del multicast

RPF (Reverse Path Forwarding) es el mecanismo que evita loops: cuando un router recibe un paquete multicast, comprueba que llegó por la interfaz que usaría para enviar tráfico unicast hacia el origen. Si no, lo descarta. Así garantiza que el flujo viaja "alejándose" de la fuente sin dar vueltas.

Corrección al material original El material usa ip multicast-routing distributed: la palabra distributed solo aplica a plataformas con line cards distribuidas (routers de gama alta) y dará error en equipos comunes o simuladores. Lo correcto en general es simplemente ip multicast-routing. En RouterOS, además, el paquete PIM se instala aparte y la sintaxis exacta varía según la versión.

Comandos esenciales — Cisco

# Habilitar el enrutamiento multicast globalmente
ip multicast-routing

# Activar PIM Sparse-Mode en cada interfaz relevante
interface gi0/0
 ip pim sparse-mode
interface gi0/1
 ip pim sparse-mode

# Rendezvous Point estático
ip pim rp-address 10.0.0.1

# Rendezvous Point dinámico (Auto-RP)
ip pim send-rp-announce loopback0 scope 16
ip pim send-rp-discovery loopback0 scope 16

# IGMP Snooping en el switch
ip igmp snooping
ip igmp snooping vlan 10

# Verificación
show ip mroute
show ip mroute 239.1.1.1
show ip pim neighbor
show ip pim rp mapping
show ip igmp groups

Interoperabilidad con MikroTik (RouterOS)

# PIM (requiere el paquete correspondiente instalado)
/routing pim
set enabled=yes

# Alternativa sencilla: IGMP Proxy
/routing igmp-proxy
add interface=ether1 upstream=yes      # hacia la fuente
add interface=ether2                   # hacia los receptores
Nota Las versiones recientes de RouterOS reorganizan los menús de routing. Verifica la sintaxis exacta de PIM/IGMP-proxy en la versión que estés usando antes de aplicar estos comandos.

Diagrama de la topología

Laboratorio 6: el router replica el stream una sola vez; añadir clientes no duplica el tráfico en el enlace de origen.

Laboratorio 6 — Multicast IPTV

Topología: Servidor de Video → Router Cisco (PIM-SM) → Switch → Clientes.

  1. Habilitar ip multicast-routing en el router Cisco.
  2. Configurar PIM Sparse-Mode en todas las interfaces relevantes.
  3. Definir el RP (puede ser el mismo router).
  4. Habilitar IGMP Snooping en el switch para la VLAN de los clientes.
  5. Desde el servidor, enviar el stream al grupo 239.1.1.1.
  6. Desde un cliente, suscribirse con VLC: udp://@239.1.1.1:1234.
  7. Verificar con show ip mroute que el flujo está activo.
  8. Agregar un segundo cliente y comprobar que el router NO duplica el tráfico en el enlace de origen.
Verificación Con dos clientes viendo el video, el ancho de banda en el enlace servidor→router debe mantenerse en un único flujo; en show ip mroute aparece la entrada (*, 239.1.1.1) con las interfaces salientes pobladas.

Resumen del bloque

  • Multicast envía un solo flujo a un grupo; la red lo replica solo donde se bifurca.
  • Los grupos usan direcciones clase D (224.0.0.0 – 239.255.255.255).
  • IGMP suscribe al host con su router; IGMP Snooping evita que el switch inunde.
  • PIM enruta el multicast entre routers usando la tabla unicast existente.
  • PIM-SM (con RP) es eficiente; PIM-DM inunda y poda, solo para redes pequeñas.
  • RPF descarta paquetes que no llegan por la interfaz correcta hacia el origen, evitando loops.

¿Por qué multicast es más eficiente que unicast para streaming?
Envía un único flujo que la red replica solo donde hace falta, en vez de una copia por cada cliente.
¿Qué rango de IP usan los grupos multicast?
Clase D: 224.0.0.0 – 239.255.255.255.
¿Para qué sirve IGMP?
Para que un host se suscriba o desuscriba a un grupo multicast ante su router local.
¿Qué hace IGMP Snooping en un switch?
Inspecciona IGMP y envía el flujo solo a los puertos con receptores, en vez de inundar la VLAN.
PIM-SM vs PIM-DM
SM no envía nada hasta que se pide (árbol con RP); DM inunda todo y luego poda.
¿Qué es RPF?
Reverse Path Forwarding: descarta paquetes que no llegan por la interfaz hacia el origen; evita loops.

Cuestionario

1. ¿Qué rango de direcciones corresponde a multicast?
Los grupos multicast son direcciones clase D.
2. ¿Cuál es la función del Rendezvous Point en PIM-SM?
El RP registra emisores y atiende a los receptores hasta optimizar el árbol.
3. ¿Qué hace IGMP Snooping?
Sin snooping, el switch inunda la VLAN; con snooping, dirige el flujo.
4. PIM Dense Mode es apropiado principalmente para…
DM inunda y poda; eficiente solo si la mayoría son receptores y la red es chica.
5. ¿Qué problema previene RPF?
RPF verifica la interfaz de entrada hacia el origen; si no concuerda, descarta el paquete.
