BLOQUE 01

Switches Cisco — Fundamentos

El switch es el corazón de la red de capa 2. Antes de segmentar, enrutar o asegurar, hay que dominar cómo se accede a un switch Cisco, cómo se le da una identidad en la red y cómo se administra de forma remota y segura.

Teoría ampliada

¿Qué hace realmente un switch?

Un switch opera en la capa 2 (enlace de datos) del modelo OSI. Su trabajo es reenviar tramas Ethernet basándose en direcciones MAC. Aprende dónde está cada dispositivo construyendo una tabla CAM (Content Addressable Memory): cuando recibe una trama, asocia la MAC de origen al puerto por el que entró. Cuando debe reenviar hacia una MAC de destino conocida, envía la trama solo por ese puerto; si la desconoce, hace flooding (la envía por todos los puertos del mismo dominio de broadcast).

A diferencia de un hub (capa 1, que repite todo a todos), el switch crea un dominio de colisión por puerto, lo que permite comunicación full-duplex sin colisiones.

Los modos de la CLI de IOS

El sistema operativo de los switches Cisco se llama IOS y se administra por línea de comandos jerárquica. Entender los modos evita el 90% de los errores de un principiante:

  • User EXEC (Switch>): solo comandos de diagnóstico básico. No permite cambiar nada.
  • Privileged EXEC (Switch#): acceso completo de lectura, reinicio, guardado y depuración. Se entra con enable.
  • Configuración global (Switch(config)#): se modifican parámetros del dispositivo. Se entra con configure terminal.
  • Sub-modos de configuración: interfaz (config-if), línea (config-line), VLAN (config-vlan), etc.
Tip Salir de un modo: exit retrocede un nivel; end (o Ctrl+Z) vuelve directo a Privileged EXEC desde cualquier punto.

¿Por qué la IP va en una interfaz VLAN?

Un switch puro de capa 2 no enruta; sus puertos físicos solo conmutan tramas, no tienen IP. Para administrarlo (SSH, ping, SNMP) se le asigna una IP a una SVI — Switch Virtual Interface — que es una interfaz lógica asociada a una VLAN. Esa IP es solo de gestión: identifica al switch como un host más dentro de esa VLAN. Por defecto se usa interface vlan 1, aunque por seguridad conviene mover la gestión a una VLAN dedicada.

Acceso remoto: Telnet vs SSH

El acceso por consola (cable rollover) es local y siempre disponible, pero poco práctico para el día a día. El acceso remoto se hace por las líneas VTY (Virtual TeleType):

  • Telnet (puerto 23): transmite todo — incluida la contraseña — en texto plano. Inseguro.
  • SSH (puerto 22): cifra toda la sesión. Requiere un par de claves RSA, por eso necesita un hostname y un domain-name definidos antes de generar la clave.

La primera VLAN

Una VLAN (Virtual LAN) es un dominio de broadcast lógico. Crear la VLAN 10 con nombre USUARIOS no conecta a nadie todavía: solo la declara en la base de datos del switch. El tráfico empieza a separarse cuando se asignan puertos a esa VLAN (Bloque 2).

Corrección al material original El material original genera la clave RSA antes de definir username. El orden correcto y robusto es: hostname → ip domain-name → crypto key generate rsa → username → line vty. Además, conviene fijar ip ssh version 2, ya que SSHv1 es vulnerable.

Comandos esenciales

# Entrar a modo privilegiado y configuración global
enable
configure terminal

# Identidad del switch
hostname SW-CORE

# IP de gestión sobre la SVI (VLAN 1 por defecto)
interface vlan 1
 ip address 192.168.1.10 255.255.255.0
 no shutdown
exit

# Gateway por defecto (necesario para gestión fuera de la subred)
ip default-gateway 192.168.1.1

# Habilitar SSH (orden correcto)
ip domain-name empresa.local
crypto key generate rsa modulus 2048
ip ssh version 2
username admin privilege 15 secret Admin123
enable secret ClaveEnable123
line vty 0 15
 transport input ssh
 login local
exit

# Crear la primera VLAN
vlan 10
 name USUARIOS
exit

# Verificación
show ip interface brief
show running-config
show vlan brief
show mac address-table

# Guardar en NVRAM (cualquiera de las dos)
write memory
copy running-config startup-config
Nota enable secret guarda la contraseña cifrada; enable password la guarda en texto plano — usa siempre secret.

Diagrama de la topología

Laboratorio 1: PC de administración y router conectados al switch; acceso inicial por consola, gestión posterior por SSH.
IOS tiene modos jerárquicos: User EXEC (solo lectura básica) → Privileged EXEC (acceso completo) → Configuración Global → sub-modos (interfaz, línea VTY, VLAN). El prompt cambia en cada nivel: > / # / (config)#.

Laboratorio 1 — Configuración inicial

Topología: PC → Switch Cisco → Router.

  1. Conectar al switch por consola con cable rollover y PuTTY (9600 baud, 8-N-1).
  2. Entrar a modo privilegiado: enable.
  3. Entrar a configuración global: configure terminal.
  4. Asignar el hostname: hostname SW-CORE.
  5. Asignar IP a la SVI VLAN 1 y activarla con no shutdown.
  6. Definir ip default-gateway apuntando al router.
  7. Configurar ip domain-name, generar la clave RSA y habilitar SSH v2.
  8. Crear el usuario admin con privilegio 15 y enable secret.
  9. Verificar con show ip interface brief y probar SSH desde la PC.
  10. Guardar la configuración con write memory.
Verificación El laboratorio está bien si: (1) ping al switch responde, (2) la sesión SSH desde la PC pide usuario/clave y entra, y (3) tras reiniciar el switch la configuración persiste.

Resumen del bloque

  • El switch reenvía tramas por MAC usando la tabla CAM; crea un dominio de colisión por puerto.
  • IOS tiene modos jerárquicos: User EXEC → Privileged EXEC → Config Global → sub-modos.
  • La IP de gestión se asigna a una SVI (interfaz VLAN), no a un puerto físico.
  • SSH cifra la sesión y requiere hostname + domain-name + clave RSA; Telnet va en texto plano.
  • Crear una VLAN solo la declara; segmentar tráfico exige asignar puertos (Bloque 2).
  • running-config (RAM, volátil) debe copiarse a startup-config (NVRAM) para persistir.

Flashcards

¿Qué comando pasa de User EXEC a Privileged EXEC?
enable — el prompt cambia de > a #.
¿Qué es una SVI?
Switch Virtual Interface: interfaz lógica ligada a una VLAN que lleva la IP de gestión del switch.
¿Por qué SSH necesita hostname y domain-name?
Porque ambos forman el nombre con el que se generan las claves RSA que cifran la sesión.
Diferencia entre running-config y startup-config
running-config está en RAM (se pierde al apagar); startup-config está en NVRAM (persiste).
¿Qué muestra show ip interface brief?
El estado (up/down) y la IP de todas las interfaces del switch.
¿Para qué sirven las líneas VTY?
Son las sesiones virtuales que permiten el acceso remoto por Telnet o SSH (normalmente 0–15).

Cuestionario

1. ¿En qué modo se puede modificar la configuración del switch?
User EXEC solo diagnostica; los cambios se hacen en config global (configure terminal).
2. La IP de gestión de un switch L2 se configura en…
Un switch L2 no enruta; la IP va en una SVI asociada a una VLAN.
3. ¿Qué ventaja principal aporta SSH frente a Telnet?
Telnet envía todo en texto plano; SSH cifra la sesión completa.
4. ¿Qué comando guarda la configuración para que sobreviva a un reinicio?
Copia la config de RAM a NVRAM; equivale a write memory.
5. Crear vlan 10 con name USUARIOS…
Declarar la VLAN no mueve tráfico; hay que asignar puertos access o trunk.
